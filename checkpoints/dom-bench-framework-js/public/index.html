BEHIND THE NUMBERS

A fair test starts with the setup.

Each framework runs alone in a 1,100 × 650 pixel iframe, using identical task data, row markup, CSS, and stable task IDs. All rows are rendered; there is no virtualization.

The workload

Render 100, 500, and 1,000 tasks into an empty mounted app. Update the names and priorities of the first 50 tasks in a fresh 1,000-task list. Delete the first 50 from another fresh 1,000-task list.

The clock

Generate data outside the timer. Measure with performance.now(), wait for the framework's DOM commit, and read offsetHeight to force layout. These timings exclude network, framework startup, fixture preparation, and paint. Every measured result is checked against the actual DOM.

The protocol

Three warm-ups, then ten measured runs per case. Report the median and retain every raw sample. The browser runner uses a fixed framework order. The automated runner uses fresh pages and a seeded shuffled order. Keep the tab foregrounded, close busy apps, and compare results from the same browser and machine.

Read with context

React uses flushSync, Vue nextTick, Svelte tick, and Angular explicit change detection. Angular runs production mode with JIT templates compiled before timing; it is not an Angular CLI AOT build. Its ngModel form controls add work beyond simple property bindings. Small differences can be measurement noise. These results describe this workload, not a universal framework ranking.

Heap measurements use CDP after garbage collection. They describe JavaScript heap deltas, not total browser or DOM memory. In-page runs do not collect memory.
